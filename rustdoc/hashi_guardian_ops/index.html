The guardian operator’s steps. It drives the guardian’s infrastructure (Pulumi, AWS, the proxy) from the latest checkout, and takes everything that must match the guardian from the guardian’s own commit: see commit.

Modules§

ask
Questions to the operator before a step changes anything.
commit
The guardian’s own commit. Everything that must match the guardian (its CLI, its protos, the key provisioners’ scripts) comes from the tree at that commit, never from the checkout this tool runs from.
env
The operator’s environment file: KEY=VALUE lines naming the guardian stack and its key provisioners.
exec
External commands. Every step reaches Pulumi, AWS, GitHub, git, cargo and the guardian only through Exec, so tests can stand in for all of them at once.
github
GitHub Actions runs: the guardian’s PCR0 measurement, which must come from two independent runners, and the proxy image build.
guardian
What a guardian reports about itself: through a slot’s tunnel, through the proxy’s relay, and on the proxy’s public /info. gRPC answers are decoded by grpcurl with the guardian commit’s own protos, so this tool never reads a guardian with another build’s field or enum numbering.
host
A guardian host: the user-data it was launched with, and commands on it through SSM.
kp_bucket
The key provisioners’ bucket, KP_BUCKET: KPs upload their public keys to it with a shared upload key, and the operator publishes the guardian configuration to its _config/ prefix. The bucket comes from the infrastructure, which must let that key read _config/ and the guardian’s log bucket but never write _config/, since it names the build every key provisioner will trust. From hashi #1464 on, the signers of a KP-set rotation upload their submissions to its _rotate-kp-set/ prefix.
plan
Pulumi previews and updates. A target that names nothing is no error to Pulumi, so every step compares a plan’s changes with exactly what it expects before applying it.
proxy
The guardian proxy’s stack, applied from its program at GUARDIAN_PROXY_PULUMI_DIR so the proxy follows the enclave stack’s slots. Following them changes only the proxy task’s two guardian URLs; anything else in a plan stops the step.
render
A slot’s configuration: guardian-init.yaml for the key provisioners and operator.yaml for the operator, beside the certificates they list. Both name everything the operator and the key provisioners must agree on, with the endpoint each reaches the guardian by.
stack
The guardian enclave’s Pulumi stack, read fresh by every step so none acts on a remembered value. The stack has two slots, a and b; its outputs follow the active one and name the other as the standby.
steps
One function per operator step. Each reads what it acts on fresh, checks it, asks before changing anything, acts, and checks the result.
sui
The Sui epoch, from Sui GraphQL. hashi’s committee hands off to the guardian once per epoch, so a switchover must sit well inside one.
