The snapshot a continuous audit resumes from after a restart. The continuous auditor’s snapshot: the whole audit state, so a restart continues where the last run stopped.

Why it exists: without it, every restart would re-audit from the bridge’s genesis to rebuild the UTXO pool, and report every old finding again.

How it works:

  1. About once an hour, the auditor saves a Snapshot: the deployment it audits, its AuditState, and the UTXO pool. The audit state is the position of each poller, every open state machine, the suspect spends of the last pool check. All of it is taken at one instant.
  2. A restart loads the machines and resumes each poller at its saved position. It reads no event twice and skips none, so no flow is cut in two.
  3. The bucket holds the snapshot as one object, SNAPSHOT_KEY. A save replaces it whole.

Assumptions:

  • Only the monitor writes the bucket.
  • A snapshot of another SNAPSHOT_VERSION fails the load. The operator deletes it, and the next start is a first run from genesis.
  • The snapshot is durable. Without it, the next start is a first run from genesis, which needs a Sui node that keeps the history.
