hashi_monitor::audit

Module continuous 

Source
Expand description

The continuous auditor: a long-running monitor of the live bridge.

Why it exists: the deployed monitor must report a late or contradictory event soon after it happens, and alerting reads its metrics.

How it works:

  1. The start is on the guardian timeline. A snapshot this deployment saved sets it to the snapshot’s restart start, unless --start is earlier. Without one, it is --start, or far enough back to re-audit a DEFAULT_RESTART_LOOKBACK outage and the checks that were pending when it began. Sui polling starts Timing::sui_lookback before it, and guardian polling Timing::guardian_lookback before it.
  2. At startup, each source catches up once. A source that fails is logged and retried on its next tick.
  3. Then the Sui, guardian and Bitcoin ticks run every POLL_INTERVAL, and the state checks every STATE_TICK_INTERVAL: fetch the missing Sui approvals, report the violations, garbage collect, log the progress watermarks, and save the snapshot one state check behind.
  4. Every finding is logged and recorded in the metrics, and each source’s checked-through time is exported.

Assumptions:

  • A poll failure is transient. The auditor logs it and goes on; only a failure to start is an error.
