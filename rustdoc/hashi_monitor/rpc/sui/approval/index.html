Withdrawal-side checks on the Hashi approvals that the monitor reads from Sui.

Why it exists: Move validates a withdrawal’s user outputs against the user requests, but not its txid or its change outputs. A compromised committee controls both, so the monitor checks them here before an approval enters the state machine.

Goals of the approval checks, together with Move and the state machine:

  1. The transaction the guardian signs is the one posted on Sui: the same input UTXOs and the same output UTXOs.
  2. Every output is either a user-requested payout, with the requested amount less the fee share, or change to a Hashi address.

Chain of trust, from the user’s request to the guardian’s signature:

  1. Move builds the WithdrawalTransaction object in new_withdrawal_txn (withdrawal_queue.move). It asserts that each user output pays the request’s address and the request’s amount less the per-user miner fee, and it caps that fee. The inputs are copied from the UTXO pool by id in commit_withdrawal_tx (withdraw.move). Change outputs are not checked.
  2. commit_withdrawal_tx then calls emit_withdrawal_picked_for_processing, which emits WithdrawalPickedForProcessing from that object’s own fields. So the event carries the object’s txid, inputs and outputs to this file.
  3. This file rebuilds the transaction from those inputs and outputs and rejects the approval if the claimed txid differs.
  4. The guardian computes its own txid from the outputs it signs, and the state machine requires the guardian’s txid to equal the approval’s. Together: the guardian signed exactly the outputs that Move validated.
  5. A txid does not commit to which outputs Sui calls change, so the event carries the inputs and outputs in Move’s shape, and the state machine requires the guardian’s log, converted into that shape, to be equal. The guardian derives every change address from a path it logs, so equality means each change output pays the bridge, which completes both goals.

Assumptions:

  • The two keys every bridge address derives from never change. The caller reads them once.
  • An approval comes from a WithdrawalPickedForProcessing event.
