The YAML config file: the identity of one deployment. The monitor’s config file: the identity of one deployment.

Why it exists: the file holds what differs between environments or changes over time, such as the guardian bucket, the accepted enclave builds, the Hashi package and the RPC endpoints. The timing bounds describe the protocol and are the same everywhere, so they live in timing, not here.

How it works:

  1. load_yaml parses the file into a YAML tree.
  2. Every string value of the form env:NAME is replaced by the value of the environment variable NAME. This keeps bucket names, endpoints and credentials out of the file.
  3. The tree is deserialized. Unknown keys are an error, so a typo cannot be ignored.

Assumptions:

  • audit.sample.yaml is the reference for the file’s shape. The deployment in sui-operations stores that shape verbatim.
